# Obsidian learning and recall

**Recommendation: design Clear around finding, understanding, and selectively remembering knowledge.** Use substantial topic notes, curated hubs, and compact recall sections with hidden answers. Original ideas and practical references do not automatically need daily memorization. Start with Excalidraw and Obsidian Spaced Repetition (OSR), supported by native Mermaid, Canvas, Templates, Bases, links, and callouts. Connect them through Home/Learn/Review/Ideas/Reference/Maps/Garden. Ideaverse supplies navigation patterns, but its public product is a configured vault, not evidence that every workflow belongs in Clear. This report proposes a design; no personal vault or live integration was inspected. ([Ideaverse](https://www.linkingyourthinking.com/ideaverse-pro))

## Three note roles keep learning and thinking manageable

**Proposed roles:** a **Learning** note explains a concept, an **Idea** note develops an original possibility, and a **Reference** note preserves material useful to consult. These are purposes, not mandatory folders or mutually exclusive identities. A learning page can become a reference; an idea can link to both without being scheduled for recall. A checklist, changing plan, quotation, or speculative hypothesis often needs application or reconsideration rather than memorization. This distinction is a methodological recommendation, not a tested Obsidian taxonomy. Concept-oriented notes let knowledge from several sources accumulate together; an inbox holds incomplete captures until they merit development, merging, archiving, or deletion. ([Concept-oriented notes](https://notes.andymatuschak.org/Evergreen_notes_should_be_concept-oriented), [Writing inbox](https://notes.andymatuschak.org/A_writing_inbox_for_transient_and_incomplete_notes))

**Recommended learning-note outline:** “What problem it solves”; topic headings explaining the mechanism; one worked example; a meaningful diagram where relationships need showing; assumptions and failure cases; “Try from memory”; sources and connections. Omit irrelevant sections. Keep recall compact and subordinate to the explanation, rather than turning navigation into a hierarchy of questions. Update an existing topic first. Split a section when it becomes independently useful or makes the parent difficult to navigate, leaving context and a link behind. Atomicity does not require maximum fragmentation; even its advocates acknowledge tradeoffs in cohesion. Heading and block links provide useful intermediate granularity without another file. ([Atomic notes](https://notes.andymatuschak.org/Evergreen_notes_should_be_atomic), [Obsidian links](https://obsidian.md/help/links))

An Idea outline should expose the problem, proposed mechanism, assumptions, evidence, and smallest useful experiment. Mark speculation visibly. A Reference outline should state when to use it, steps or information, expected result, source, and verification date where facts can drift. Neither role automatically enters a study queue.

**Hubs explain relationships; filtered views manage lists.** A “Robot localization” hub can guide readers through Foundations, Estimation, Implementation, and Experiments. A Base can list unfinished captures, but cannot decide prerequisite order. Maps of Content are an author practice, not evidence of superior retention. Use folders for storage boundaries, properties for consistent fields, tags for cross-cutting labels, and links for concepts. A small proposed schema—`kind`, `status`, and linked `topics`—is enough initially. Avoid duplicating the taxonomy across mechanisms. ([Maps of Content](https://blog.linkingyourthinking.com/maps/), [Properties](https://obsidian.md/help/properties), [Tags](https://obsidian.md/help/tags), [Bases](https://obsidian.md/help/bases))

## Recall works when answers stay hidden until attempted

**Evidence supports retrieval practice and spacing**, not a particular note appearance. Retrieval outperformed repeated study on delayed prose tests, while restudy performed better immediately; familiarity is therefore a poor substitute for an attempted answer. A broader review rated practice testing and distributed practice highly, but this does not make readable summaries useless as references. Spacing research also found that useful gaps depend on the intended retention delay, so no universal interval sequence follows from it. ([Roediger and Karpicke, 2006](https://www.psychologicalscience.org/journals/psychological-science/j.1467-9280.2006.01693.x/), [Dunlosky et al., 2013](https://acs.ist.psu.edu/ist521/dunloskyRMNW13.pdf), [Cepeda et al., 2008](https://doi.org/10.1111/j.1467-9280.2008.02209.x))

**Recommended loop:** select something worth remembering, attempt with the explanation hidden, reveal and compare, correct, and revisit later. Include explanation, reconstruction, and application alongside factual questions. Corrective feedback improved subsequent recall and reduced errors in a multiple-choice experiment. Repair misunderstood explanations, limit additions when reviews accumulate, and suspend obsolete material. These controls are practical choices; research does not prescribe an optimal daily duration, card count, or scoring scale. ([Butler and Roediger, 2008](https://pubmed.ncbi.nlm.nih.gov/18491500/))

Use **selected cards for precise targets** and **whole-note study for coherent understanding**. A card can ask what a parameter means; a topic review can ask the learner to explain a mechanism, redraw it, and solve a changed example. OSR provides Markdown flashcards and a separate tagged whole-note review queue. Whole-note review opens the note and asks for a rating; it does not automatically conceal the explanation or assess understanding. Put the prompt before a collapsed answer, or open a prompt-only surface first, and rate after retrieval. Native foldable callouts provide concealment without scheduling. ([OSR cards](https://stephenmwangi.com/obsidian-spaced-repetition/flashcards/q-and-a-cards/), [OSR note review](https://stephenmwangi.com/obsidian-spaced-repetition/notes/), [Callouts](https://obsidian.md/help/callouts))

**Scheduler distinction:** OSR release 1.15.0 added opt-in FSRS for flashcards. Its implementation retains the existing OSR scheduling path for whole-note review; older documentation saying FSRS is merely planned is stale. Clear should delegate scheduling to the installed scheduler, not silently modify its storage or promise an API that has not been checked. ([Release 1.15.0](https://github.com/st3v3nmw/obsidian-spaced-repetition/releases/tag/1.15.0), [Implementation PR](https://github.com/st3v3nmw/obsidian-spaced-repetition/pull/1425))

## Diagrams should explain relationships and become recall tasks

A useful visual answers a question: what causes what, where information flows, how quantities vary, or how concepts differ. Label arrows and axes. **Recommended convention:** use a few consistent colors for recurring roles, label those roles explicitly, use solid arrows for the main process and dashed arrows for assumptions or optional relationships, and add a short caption. Color should reinforce meaning rather than carry it alone. This is a usability choice, not a learning-style prescription.

During recall, hide the diagram, reconstruct its essential structure, explain the connections, then compare. Judge missing relationships and wrong directions rather than artistic quality. Ask what changes if an assumption or parameter changes. Research found that concept maps made from memory and paragraph recall both outperformed further study, without a significant difference between those retrieval formats. Drawing research also found benefits over copying, while thoughtful paraphrasing performed comparably in one experiment. The implication is active meaning-making, not guaranteed superiority of pictures. ([Blunt and Karpicke, 2014](https://learninglab.psych.purdue.edu/downloads/2014/2014_Blunt_Karpicke_JEDP.pdf), [Wammes et al., 2017](https://pubmed.ncbi.nlm.nih.gov/28756291/))

| Tool | Recommended job | Documented boundary |
| --- | --- | --- |
| Excalidraw | Sketch geometry, uncertainty, mechanisms; embed editable drawings in topic notes | Community renderer required; image export supplies a portable preview. ([Maintainer](https://github.com/zsviczian/obsidian-excalidraw-plugin)) |
| Native Mermaid | Stable process and relationship diagrams written in Markdown | Diagram note links do not appear in Graph view; keep ordinary wikilinks too. ([Formatting](https://obsidian.md/help/advanced-syntax)) |
| Native Canvas | Explore relationships across several notes with labeled connections | Embedded canvases currently show shapes without card text; open the canvas or export an image. ([Canvas](https://obsidian.md/help/plugins/canvas), [Embeds](https://obsidian.md/help/embeds)) |
| Native Graph | Find linked notes and navigate a neighborhood | Edges represent note links, not conceptual mastery or typed causal relationships. ([Graph](https://obsidian.md/help/plugins/graph)) |
| Anki | Mask labels or components when image occlusion is essential | Native image occlusion works on images; export a drawing first. ([Anki manual](https://docs.ankiweb.net/manual/editing#image-occlusion)) |

**Worked design example: `Kalman filter`.** Begin with a robot estimating one-dimensional position, then explain predict → measure → correct. In an illustrative scalar correction, predicted position is 10 m with variance 4 m², and the measurement is 12 m with variance 1 m². Under the simple independent-error model, the gain is `4/(4+1)=0.8`; the corrected position is `10 + 0.8(12−10)=11.6 m`. This calculation makes “trust the less uncertain estimate more” concrete. Draw the prediction and measurement converging on correction, labeling the uncertainty inputs. Later connect the explanation to `[[Covariance]]` and `[[Extended Kalman filter]]`.

The compact recall section can ask: “Explain why the correction moves toward the measurement”; “Reconstruct the information-flow diagram”; and “What happens if measurement variance rises to 9 m²?” The illustrative answer is gain `4/13≈0.308` and corrected position `≈10.62 m`, so the measurement has less influence. Hide these cues until attempted. A separate application task asks when an incorrect noise assumption would make the estimate misleading. The example demonstrates the proposed note structure, not a complete derivation or production estimator specification.

## A minimal stack gives Clear a focused responsibility

**Recommended starting stack: Excalidraw + OSR**, with native Mermaid, Canvas, Templates, Bases, links, search, backlinks, and callouts. Templates cover reusable note skeletons; Bases covers filtered property views without creating another note database. Add draw.io only when precise engineering diagram libraries are a repeated need, or a Markmap tool when outline-to-map conversion saves meaningful work. Avoid installing overlapping tools merely because they exist. ([Templates](https://obsidian.md/help/plugins/templates), [Bases](https://obsidian.md/help/bases))

Choose Anki instead for a workflow dominated by image occlusion; do not schedule the same material in two systems. OSR documents image card content, making exported PNG/SVG diagram answers a reasonable starting point. **Live Excalidraw or Mermaid rendering inside OSR review remains unverified.** An Obsidian-to-Anki bridge introduces AnkiConnect and export dependencies and does not establish automatic transfer of editable drawings or occlusion masks. ([OSR](https://github.com/st3v3nmw/obsidian-spaced-repetition), [Anki bridge](https://github.com/ObsidianToAnki/Obsidian_to_Anki))

**Proposed Clear scope:** Home surfaces current topics and capture; Learn navigates substantial learning notes; Review opens deliberately selected study and scheduler queues; Ideas develops possibilities; Reference finds useful lookup material; Maps opens curated hubs and canvases; Garden revisits neglected captures, weak connections, and unfinished thinking. Garden is an editorial queue, not a disguised learning scheduler. Borrow Ideaverse's discoverable navigation while giving learning and recall priority over reproducing its Calendar, Efforts, or every collection. ([Ideaverse](https://www.linkingyourthinking.com/ideaverse-pro))

These learning priorities refine the original Ideaverse-inspired proposal; they do not cancel Calendar, Efforts, or other earlier objectives. Their place in the eventual scope remains a design decision, and no implementation approval is implied.

Map these views onto existing files, folders, properties, and templates. Existing-vault setup should not require moving notes; views are lenses rather than compulsory new directories. Offer visible commands to find an existing topic, update it, create a linked diagram, or mark selected material for review. Preview the destination and require deliberate selection before adding memory obligations. Integration adapters should use verified commands or supported APIs for installed versions; fallback links can still open the note or drawing. Clear's initial responsibility is navigation, authoring assistance, and explicit workflow choices.

## Conclusion

Judge the design by whether the user can locate an explanation, answer without seeing it, correct a mistake, and apply the idea. Note count, graph density, and completed reviews are insufficient proxies. Test one topic through editing, diagram embedding, hidden-answer review, and export in a disposable vault on the intended devices before promising integration. This report supports a direction; it does not establish compatibility or approve implementation.
